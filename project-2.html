Overview

This lab was completed as part of EEET2368 Network Fundamentals and Applications at RMIT University. Working in a pair, we designed, configured and analysed an IP-based packet-switched Wide Area Network using Cisco Packet Tracer. The network connected four separate LANs through a topology of four edge routers and one core router, built up step by step from individual LANs through to a fully interconnected WAN.

The lab covered the full process of bringing a WAN to life — from configuring IP addresses and subnet masks on every device, to enabling dynamic routing with RIP, to stress-testing the network by simulating link failures and observing how traffic rerouted itself in real time.

What We Built

  • Four LANs — Network 1 (3 PCs), Network 2 (2 PCs), Network 3 (2 PCs), Network 4 (1 PC), each connected via a 2960 switch
  • WAN topology — four edge routers connecting each LAN to the wider network, plus a core router providing a redundant path between edge routers
  • IP addressing & subnetting — configured /24 subnet masks across all devices, with router-to-router links on separate 10.x.x.x address ranges
  • RIP dynamic routing — enabled Routing Information Protocol on all routers so they could automatically update their routing tables and discover paths across the full network
  • Connectivity testing — verified communication using ping across all networks and traceroute to map the exact path packets took between any two devices
  • Link redundancy testing — simulated link failures by disabling router interfaces mid-ping, observing how the network detected the failure, recalculated routes, and restored communication through alternative paths

Key Findings

One of the most interesting parts of the lab was watching packet-switched routing respond to failure in real time. When a link was disabled during an extended 200-packet ping, there was a brief window of dropped packets — the routing convergence period — before RIP updated the tables and traffic found an alternative path automatically.

We also explored the difference between circuit-switched and packet-switched networks through the lens of delay: circuit switching gives deterministic delay because it reserves a dedicated path, while packet switching shares bandwidth dynamically, meaning delays vary with congestion and queuing. Testing both simultaneous pings from different sources through shared links made this concept tangible rather than theoretical.

  • Single link disabled — RIP rerouted traffic through the core router after a short convergence delay, communication restored
  • Both paths to Edge Router 3 disabled — no alternative path existed, packets timed out entirely, demonstrating why redundancy matters
  • Traceroute analysis — confirmed exact hop-by-hop paths, observed that switches don't appear in traceroute output (Layer 2 vs Layer 3)

What I Learned

This lab made routing protocols feel real. Reading about RIP in lectures is one thing — watching it detect a broken link and reroute 200 live packets through a different path is another. It also made the trade-offs in network design very concrete: more redundant links mean more resilience, but there's always a convergence gap where packets are lost while the network figures out the new topology.

  • Cisco Packet Tracer — built and configured a multi-router WAN topology from scratch
  • IP addressing & subnetting — assigned and managed addresses across 5 routers, 4 switches, and 8 PCs
  • Dynamic routing (RIP) — configured and observed how routing tables update automatically in response to topology changes
  • Network troubleshooting — used ping and traceroute to diagnose connectivity issues and verify paths
  • Redundancy & fault tolerance — simulated real failure scenarios and observed the limits of dynamic rerouting
